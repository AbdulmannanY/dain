# ابدأ من هنا: دائن (Dain)

> **لأي جلسة جديدة:** اقرأ هذا الملف كاملاً قبل أي اقتراح أو كود، ثم
> `docs/project-context.md` (المرجع التفصيلي: الشجرة، والقواعد، والسجل)، ثم
> `docs/agent-script-protocol.md` (طريقة التسليم). اقرأ المستودع الفعلي من

> وحُدّث بعد دفعة `dain-36..43`.

## 1. ما هو التطبيق

دفتر ديون مشترك بين طرفين **يؤكّده الاثنان**: صاحب المحل أو الشخص يسجّل ما
أعطى أو أخذ، والطرف الآخر يرى الدفتر نفسه ويؤكّد كل قيد أو يعترض عليه بسبب.
لا يدخل الرصيد المتفق عليه إلا ما أكّده الطرفان، والسجل لا يُحذف.

- **التطبيق:** Flutter 3.44.0 (`app/`)، عربي من اليمين لليسار، أندرويد عبر APK من CI.
- **الخادم:** Supabase، مشروع `dain-backend`، ref `mxnjwaofjlxxdjizjsfb`،
  Postgres مع RLS ودوال، والمخطط في `supabase/migrations/`.
- **صفحة الرابط:** `share/`، HTML وJS بلا تبعيات، على
  `https://abdulmannany.github.io/dain/#<token>`.
- **المستودع:** `github.com/AbdulmannanY/dain`، والمالك عبدالرحمن (صنعاء).

## 2. ما يعمل الآن

- **الدخول برقم الجوال برمز SMS حقيقي:** Send SMS Hook يرسل الرمز عبر جوال
  بوابة عند المالك (§5)، والصيغ المحلية السعودية (`05…`) واليمنية (`7…`) مدعومة.
- **«دفاتري»:** الأرصدة من جهتي، والمجاميع لكل عملة، والبحث بالاسم أو المحل أو
  الرقم، والترتيب بالرصيد أو الاسم أو المعلّق أو موعد السداد (`dain-37`).
- **دفتر جديد:** شخصي أو لمحل، بعملة ر.ي أو ر.س أو $ (الافتراضي من رقم الطرف).
- **شاشة الدفتر:** «أعطيت/أخذت» بتاريخ يُختار (لا بعد اليوم، `dain-36`)، وتأكيد
  القيد، والاعتراض بسبب إجباري، والسحب.
- **الربط التلقائي:** حين يدخل الطرف الآخر برقمه يجد الدفتر عنده.
- **رابط للطرف الآخر:** صفحة ويب يؤكّد منها أو يعترض دون تطبيق، ويطبع منها
  كشف الحساب أو يحفظه PDF (`dain-40`).
- **التذكير:** يفتح واتساب برسالة جاهزة فيها رابط، وتُنسخ أيضاً (`dain-41`).
- **موعد السداد:** يضعه المالك ويراه الطرفان، ويظهر «فات الموعد» (`dain-38`).
- **التحديث عند العودة إلى التطبيق** (`dain-39`).
- **محلاتي:** تسمية المحلات وحذف الفارغ منها.
- **حسابي:** تغيير الاسم، وسياسة الخصوصية، وحذف الحساب (`dain-32`).
- **تعديل الطرف الآخر:** الاسم دائماً، والرقم حتى ينضم (`dain-33`).
- **سياسة الخصوصية:** `https://abdulmannany.github.io/dain/privacy.html` (`dain-40`).
- **CI:** اختبارات التطبيق والقاعدة والصفحة، وAPK موقّع بمفتاح ثابت، ونشر
  الصفحة على Pages، وإبقاء Supabase نشطاً ونسخة احتياطية مشفّرة (`dain-42`).

## 4. معلّق ويحتاج المالك

1. لصق SQL `20261025000000_entry_date.sql` و`20261026000000_due_date.sql`،
   ثم تشغيل 36 إلى 43 بالترتيب بفاصل دقيقة، ثم الدفع.
2. **حذف رقم المالك التجريبي** `967774040697=123456` من Test Phone Numbers
   قبل أي مستخدم حقيقي، مع إبقاء `966500000001` و`966500000002`.
3. **SMS OTP Expiry** إلى 300 ثانية (Sign In / Providers ← Phone) إن لم يتم،
   ثم التأكد أن **Test OTPs Valid Until** في المستقبل.
4. **النسخة الاحتياطية:** سرّا `DAIN_DB_URL` و`DAIN_BACKUP_PASSPHRASE` (§5)، ثم
   Actions ← «Supabase keepalive and backup» ← Run workflow مرة للتجربة.
5. **سياسة الخصوصية:** مراجعة نصّها، والتأكد أن Issues مفعّلة في المستودع (رابط
   التواصل فيها)، أو إعطاء بريد للتواصل بدلها.
6. تجهيز المتجر: رابط سياسة الخصوصية جاهز، وبقيت الأيقونة والاسم وAAB.

## 5. إعدادات خارج المستودع (لا تُرى في الكود)

**Supabase:**
- Phone provider مفعّل، لكن Twilio بقيم وهمية: **Send SMS Hook** (Postgres،
  `public.send_sms_via_gateway`) هو الذي يرسل فعلاً.
- امتداد `pg_net` مفعّل.
- سرّان في Vault: `sms_gate_username` و`sms_gate_password`.
- Rate Limits: SMS = 30 في الساعة.
- Test numbers: `966500000001=123456,966500000002=123456` (ورقم المالك
  مؤقتاً). تاريخ صلاحيتها **رجع مرة إلى تاريخ اليوم عند تعديل الأرقام**،
  فراجعه بعد كل حفظ.
- كل migration يُلصق يدوياً في SQL Editor **قبل** سكربته. اختباره الحي يفشل
  برسالة `apply … in the SQL Editor first` حتى يُطبَّق.

**جوال البوابة** (عند المالك، يبقى في الشاحن ومتصلاً):
- تطبيق «SMS Gateway for Android™» (capcom6، APK من GitHub Releases).
- Cloud server مفعّل، وNotification channel = **SSE Only**، وPing = 60.
- صلاحية SMS عبر «السماح بالإعدادات المقيدة».
- البطارية «غير مقيّد»، و«إدارة التطبيق في حال عدم استخدامه» مطفأة.
- إن لم يصل رمز: `select status_code, content from net._http_response order by created desc limit 3;`
  ثم تبويب MESSAGES في البوابة.

**GitHub:**
- Pages: Source = GitHub Actions.
- أسرار: `DAIN_KEYSTORE_BASE64` و`DAIN_KEYSTORE_PASSWORD` و`DAIN_KEY_ALIAS`
  (`upload`) و`DAIN_KEY_PASSWORD`.
- المفتاح على جوال المالك في `~/.dain-keys/`، ببصمة SHA-256
  `12:5F:5F:48:…:C8:71`. **لا يُستبدل أبداً**، وإلا لن تُحدَّث النسخ المثبّتة.
- سرّا النسخة الاحتياطية (`maintenance.yml`):
  - `DAIN_DB_URL`: Supabase ← Connect ← **Session pooler** (IPv4؛ الاتصال
    المباشر IPv6 فقط ولا تصله مشغّلات GitHub)، مع كلمة سر القاعدة.
  - `DAIN_BACKUP_PASSPHRASE`: عبارة طويلة عشوائية تُحفظ خارج GitHub أيضاً.
    المستودع عام، فالنسخة بلا العبارة لا تُقرأ، وبدونها لا تُسترجع.
  - بدون السرّين تُتخطّى النسخة بتحذير، ويبقى الإبقاء على المشروع نشطاً يعمل.
- **الاسترجاع:** نزّل `dain-backup-N` من صفحة التشغيل، ثم:
  ```bash
  gpg -d dain-YYYY-MM-DD.sql.gpg > dump.sql
  ```
  وعلى مشروع فيه الـ migrations كلها:
  ```bash
  psql "$DB_URL" -v ON_ERROR_STOP=1 -c "set session_replication_role = replica" -f dump.sql
  ```
- GitHub يوقف الجداول الزمنية في المستودع العام بعد 60 يوماً بلا أي commit،
  فيُعاد تفعيلها من صفحة الـ workflow إن توقفت.

**Termux عند المالك:** المستخدم `dev`، والمستودع `~/dain`، والسكربتات تُنزَّل إلى
`/sdcard/Download`، و`keytool` موجود.

## 7. دروس ومزالق

- **حدّ OTP:** رمز واحد لكل رقم في الدقيقة، والأرقام التجريبية تخضع له أيضاً.
  لذلك يدخل الاختبار الحي بكل رقم مرة واحدة، **ودقيقة بين كل سكربتين**، ولا يُدخل
  إلى التطبيق بالرقم `0500000002` أثناء السكربتات (يربط الدفتر قبل الاختبار).
- **الاختبار الحي الأخير يحذف حساب ب** في كل تشغيل، والتشغيل التالي يُنشئه من جديد.
- **R8 في الإصدار** يكسر الإضافات التي تستدعي Kotlin عبر JNI بالاسم.
  `release_plugins_test.dart` يحرس القيد. ونسخ debug لا ترى هذا الخطأ.
- `.order()` في supabase_dart **تنازلية افتراضياً**.
- `pageBack()` يبحث عن تلميح «Back» الإنجليزي، فيُستخدم `find.byType(BackButton)`.
- PostgREST يعيد `P0002` بحالة HTTP 500، فالعبرة بحقل `code`.
- PKCS12 يرد «password incorrect» للملف التالف أيضاً.
- قيم الأسرار الملصوقة تحمل مسافات، وCI يقصّها.
- Play Protect يحجب APK البوابة: «مزيد من التفاصيل ← التثبيت على أي حال».
  وصلاحية SMS تحتاج «السماح بالإعدادات المقيدة».
- لوحة المفاتيح العربية في Termux تفسد الأوامر الإنجليزية الطويلة، فالسكربتات
  تُسلَّم ملفات، وأوامر التشغيل أسطر قصيرة تُنسخ.
- **عمود جديد يقرؤه التطبيق** (مثل `due_on`) يكسر التحميل حتى يُلصق الـ migration،
  فالترتيب دائماً: SQL ثم السكربت ثم الدفع ثم APK.
- `url_launcher` كان أصلاً في القفل وفي APK عبر `supabase_flutter`، فتسميته لم
  تضف حزمة. قبل أي تبعية: ابحث عنها في `pubspec.lock` أولاً.
- في اختبارات الواجهة، منتقي التاريخ بالعربية يعرض الأرقام لاتينية، وزرّه «حسنًا».

## 8. طريقة العمل مع المالك (ملزمة)

- **الرد بالعربية وباختصار**، مع عرض الأسطر المتغيّرة فقط باسم الملف، وخطوات مرقّمة 1 2 3.
- **اقرأ الشجرة الفعلية** وتحقّق من كل ملف وعمود ودالة قبل ذكرها. تتبّع السلسلة
  كاملة، من الواجهة إلى القاعدة، وابحث عن الحرّاس.
- **عند الاستئناف:** اقترح الخطوة التالية قبل أي كود.
- **عند خيارات تصميم:** قارن الإيجابيات والسلبيات في جدول، **واختر الأصح ونفّذه
  بنفسك**. سؤال واحد فقط إن تعددت القراءات فعلاً.
- **التسليم:**
  - سكربت bash لكل إصلاح، والباتش Python `str.replace` مرمَّز base64،
    و`assert` لكل مرساة، وASCII فقط.
  - **مُجرَّب على نسخة جديدة كمستخدم `dev` حتى `DONE`** قبل الإرسال.
  - **كل سكربتات الدفعة تُسلَّم معاً**. وإن كان شيء يلزم أن يكون في سكربت واحد،
    فأخبر المالك.
  - الأدوات في `tools/patchgen/`، وطريقتها في README هناك.
- `git add` بأسماء الملفات، لا `-A`. **لا push**: المالك يدفع بنفسه.
- لا placeholders، ولا تبعيات جديدة، ولا تغيير معماري دون موافقة.
- الأسرار، من كلمات سر ومفاتيح، **لا تُطلب في المحادثة**. تُوضع في Vault أو
  GitHub Secrets مباشرة.
- **أمر التشغيل الذي يُعطى للمالك:**
  ```bash
  f="$(ls -t /sdcard/Download/dain-NN-*.sh | head -1)"; echo "using: $f"; cp "$f" ~/fix.sh && cd ~/dain && bash ~/fix.sh
  ```
  ثم `git push origin main`.
