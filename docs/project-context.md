## 1. الفكرة

دفتر ديون بين طرفين للأفراد والمحلات. كل دفتر بين **مالك** (شخص، وقد يعمل
باسم محل) و**طرف آخر** يُعرَّف برقم جواله. أي طرف يسجّل قيداً، و**الطرف
الآخر** يؤكده أو يعترض عليه؛ فالرصيد المتفق عليه هو ما أكّده الطرفان.
مستقل تماماً عن مشروع نُخبة.

### الدخول بالجوال (إعداد Supabase)

Authentication ← Sign In / Providers ← **Phone**:

- **رموز SMS الحقيقية عبر جوال بوابة**: تطبيق «SMS Gateway for Android™»
  (capcom6، APK من GitHub Releases، Cloud server + Start on boot) على جوال
  المالك يرسل الرموز من شريحته. Supabase يسلّم كل رمز لـ Send SMS Hook
  (`public.send_sms_via_gateway`، migration `20261023000000`) الذي يطلب من
  `api.sms-gate.app` إرساله. يُفعَّل مرة واحدة: امتداد **pg_net**، وسرّان في
  **Vault** (`sms_gate_username`، `sms_gate_password`)، ثم Auth Hooks ← Send
  SMS ← Postgres. الأرقام التجريبية لا تمرّ بالخطاف، وحدّ Auth لرسائل SMS
  يسبقه (أبقِه منخفضاً: كل رمز يُدفع من رصيد الشريحة). pg_net غير متزامن:
  فشل البوابة يظهر «لم يصل الرمز» لا خطأً، وردودها في `net._http_response`.
  حقول Twilio (`AC000…`) لم تعد تُستخدم بعد تفعيل الخطاف.
- **Test Phone Numbers and OTPs**:
  `966500000001=123456,966500000002=123456,967774040697=123456`
  (مفصولة بفاصلة على سطر واحد). الثالث رقم المالك الحقيقي للتجربة على
  الجوال: **يُحذف قبل أي مستخدم حقيقي** وعند تفعيل SMS. الاختباران الحيّان
  يحتاجان الأولين ولا يمسّان الثالث.
- **Test OTPs Valid Until**: يجب أن يكون في المستقبل دائماً. بعده تتوقف أرقام
  الاختبار كلها ويفشل الدخول والاختبار الحي بـ `sms_send_failed`. **تعديل
  الأرقام في اللوحة أعاده مرة إلى تاريخ اليوم**، فراجعه بعد كل حفظ.
- الحفظ يتم بزر Save **داخل لوحة Phone** نفسها.

## 3. بيئة التطوير

- كل العمل على Android: Termux ← proot-distro Ubuntu، المستخدم `dev`،
  المستودع في `/home/dev/dain`.
- اعتماد git خاص بدائن فقط: `credential.helper = store --file=/home/dev/.git-credentials-dain`
  (لا يمسّ نُخبة). التوكن fine-grained باسم **dain-push-2**، وصلاحياته على
  المستودع: **Contents = Read and write** و**Workflows = Read and write**.
  بدون Workflows يرفض GitHub أي دفع يلمس `.github/workflows/`
  (`refusing to allow a Personal Access Token ... without workflow scope`).
- GitHub Pages يُفعَّل مرة واحدة: Settings ← Pages ← Source: **GitHub Actions**.
  بدونه يفشل workflow «Share page deploy» (هذا ما حدث في تشغيله الأول).
- لا يُبنى APK محلياً (NDK غير متاح على ARM داخل proot)؛ يُنزَّل من CI (§7).
- **مفتاح التوقيع** على الجوال فقط: `~/.dain-keys/upload.jks` وكلمة سره في
  `~/.dain-keys/password.txt` (صلاحية 600)، ونسخة احتياطية خارج الجوال. ولّده
  `dain-16-keystore.sh` مرة واحدة ويرفض استبداله. **لا يُستبدل أبداً**: تطبيق
  موقّع بمفتاح آخر لا يُحدّث النسخة المثبّتة. في GitHub أربعة أسرار:
  `DAIN_KEYSTORE_BASE64` و`DAIN_KEYSTORE_PASSWORD` و`DAIN_KEY_ALIAS` و
  `DAIN_KEY_PASSWORD` (`/settings/secrets/actions`).
- إعدادات المستودع على الجوال تحت **More ▾ ← Settings**؛ و`github.com/settings/...`
  إعدادات الحساب لا المستودع.
  المعاينة عبر:

  ```bash
  cd ~/dain/app && flutter run -d web-server --web-port 8081 --web-hostname 0.0.0.0
  ```

  ثم `http://localhost:8081` في متصفح الجوال.

## 5. قاعدة البيانات (المخطط المطبّق والمتحقَّق منه)

**اصطلاح الإشارة، دائماً نسبةً لمالك الدفتر:**
`out` = المالك أعطى الطرف (الطرف مدين أكثر)، `in` = الطرف أعطى المالك.
الرصيد > 0 يعني أن الطرف مدين للمالك. المبالغ أعداد صحيحة بالهللة
(500.00 ر.س = 50000)، والحد 1..100,000,000,000.

**تطبيق migration على الإنتاج يدوي:** Supabase ← SQL Editor ← لصق الملف ←
Run، **قبل** تشغيل السكربت الذي يضيفه (اختباره الحي يفشل حتى يُطبَّق، ويقول
ذلك في رسالته). CI يطبّق كل الملفات بالترتيب على `postgres:17` نظيفة.

**الاعتراض يحتاج سبباً** (`20261021000000`): `_apply_response` يرفض
`disputed` بلا سبب بعد `btrim` بـ `22023`، بعد فحص الحالة (فالمؤكد يبقى
`55000`)، ويخزّن الملاحظة مقصوصة. يسري على `respond_entry` و`respond_by_token`.

| الجدول | أهم الأعمدة والقيود |
|---|---|
| `profiles` | `id` = `auth.users.id`، `full_name` 1..80 |
| `businesses` | `owner_id` (افتراضي `auth.uid()`)، `name` 1..80 |
| `ledgers` | `owner_id`، `business_id` اختياري (يجب أن يملكه نفس المالك)، `counterparty_name`، `counterparty_phone` بصيغة E.164 بلا `+` (`^[1-9][0-9]{7,14}$`)، `counterparty_id` (لا يضبطه إلا `link_my_ledgers`)، `currency` (افتراضي SAR)، `remind_every_days` 1..90، `due_on` موعد السداد (اختياري، `20261026000000`)، فريد على `(owner_id, business_id, counterparty_phone)` مع NULLS NOT DISTINCT |
| `entries` | `direction` (`out`/`in`)، `amount_minor`، `note` ≤200، `occurred_on`، `status` (`pending`/`confirmed`/`disputed`/`voided`)، `response_note`، `responded_via` (`app`/`link`)، `created_by`، `kind` (`debt` افتراضياً أو `payment`، `20261027000000`، لا يُعدَّل) |
| `entry_events` (`20261028000000`) | سجل كل قيد: `event` (`created`/`confirmed`/`disputed`/`voided`)، `actor` (null للرابط وللحساب المحذوف)، `via`، `note` (سبب الاعتراض)، `at`. يكتبه trigger فقط، ويقرؤه الطرفان |
| `share_links` | رابط واحد لكل دفتر، يُخزَّن SHA-256 للرمز فقط، `expires_at` |
| `ledger_balances` (view, security_invoker) | `confirmed_balance_minor`، `open_balance_minor` (مؤكد + معلّق)، `pending_count`، `disputed_count` |

**الحرّاس:**

- RLS على كل الجداول. الطرف الآخر يرى الدفتر فقط بعد ربطه
  (`counterparty_id = auth.uid()`). لا سياسة حذف للدفاتر.
- الصلاحيات مضيَّقة بالأعمدة: إدخال `entries` يقبل
  `id, ledger_id, direction, amount_minor, note, occurred_on, kind` فقط، وبحالة
  `pending`. تغيير الحالة عبر الدوال فقط، ولا شيء آخر في القيد يُعدَّل أو يُحذف
  (§15 في فحوص القاعدة). `id` يصنعه التطبيق (`newEntryId`)، فإعادة الإرسال بعد
  جواب ضائع ترتطم بالمفتاح الأساسي (`23505`) ويعدّها التطبيق محفوظة.
- trigger `entries_guard_payment` (`20261027000000`، عند إدراج `payment`، security
  definer): يقفل صف الدفتر `for update`، ويرفض سداداً يتجاوز ما على الدافع، أي
  الرصيد المتفق عليه من جهته ناقص دفعاته المعلّقة والمعترض عليها، بـ `23514`.
  اتجاه الدفعة هو الدافع: `in` = الطرف الآخر دفع، `out` = المالك دفع. القفل هو
  ما يمنع دفعتين متزامنتين من تجاوز المتبقي معاً (`concurrency_test.sh`).
- trigger `entries_log` (`20261028000000`، بعد الإدراج وبعد تغيير `status`،
  security definer): يكتب `entry_events`. لا منح كتابة لأحد، وanon لا يقرأ.
  القيود الأقدم أُضيف لها `created` وآخر رد له وقت، بلا فاعل؛ والسحب القديم بلا
  وقت فلم يُضف.
- trigger `ledgers_guard_phone`: لا يتغير الرقم بعد الربط، وأي تصحيح للرقم
  يحذف رابط المشاركة.
- trigger `entries_guard_day` (`20261025000000`، عند الإدراج): `occurred_on`
  بعد `current_date + 1` يُرفض بـ `22023`. اليوم بتوقيت الخادم (UTC) واليوم
  في التطبيق يسبقه حتى يوم (UTC+3)، فيُسمح بيوم واحد. `occurred_on` لا يُعدَّل.
- `due_on` ممنوح التعديل، وسياسة `ledgers_update` تحصره في المالك: تعديل
  الطرف الآخر لا يجد صفاً.

**الدوال (RPC):**

| الدالة | لمن | ماذا تفعل |
|---|---|---|
| `link_my_ledgers()` | authenticated | تربط كل دفتر مسجّل على رقمي **المؤكَّد** (`phone_confirmed_at`)؛ تتطلب ملفاً شخصياً (وإلا `42501`)؛ ترجع العدد؛ متكررة بأمان |
| `respond_entry(id, decision, note)` | authenticated | الطرف **الآخر** يؤكد أو يعترض؛ `pending→confirmed/disputed`، `disputed→confirmed` |
| `void_entry(id)` | authenticated | المنشئ يسحب قيداً معلّقاً أو معترضاً عليه. المؤكد لا يُعدَّل، يُصحَّح بقيد معاكس |
| `create_share_link(ledger, days)` / `revoke_share_link` | المالك | رابط لمن لا يملك التطبيق (1..90 يوماً)، والرمز يُرجَع مرة واحدة |
| `get_shared_ledger(token)` / `respond_by_token(...)` | anon | صفحة ويب للتأكيد بلا تطبيق؛ يستطيع التأكيد فقط على قيود سجّلها المالك. `get_shared_ledger` يرجع `kind` لكل قيد (`20261027000000`) |

## 6. التطبيق (ما بُني)

**تسلسل الدخول** (`SessionController`):
`starting` ← `enterPhone` ← `enterCode` ← `needsProfile` (إن لم يوجد ملف)
← `ready`، مع `failed` وزر إعادة محاولة.

- `link_my_ledgers()` يُستدعى عند **كل** دخول إلى `ready`، وليس أول مرة فقط،
  لأن من يسجّل ديناً برقمك لاحقاً يجب أن يظهر عندك في الفتح التالي.
- `normalizePhone` تقبل الصيغ المحلية **السعودية** (`05…`، `5…` ← `9665…`)
  و**اليمنية** (`07…`، `7…` ← `9677…`)، وجوالاتهما لا تتداخل، و`966`/`967`
  بلا `+`، والفواصل والأرقام العربية والفارسية، وتنتج صيغة قيد
  `counterparty_phone` نفسها. أي دولة أخرى تحتاج `+` أو `00`: الرقم المجرّد
  لا يُقرأ دولياً أبداً (كان `774040697` يُرسل إلى `+7`). 966 يجب أن يكون
  `9665XXXXXXXX` و967 `9677XXXXXXXX`. الرسالة والتلميح ثابتان في
  `invalidPhoneMessage` و`phoneHint`.
- إنشاء الملف الشخصي متكرر بأمان: عند `23505` يُقرأ الملف الموجود.

**«دفاتري»** (`LedgersScreen`):

- استعلامان عبر RLS: `ledgers` مع
  `business:businesses(name)` و`owner:profiles!ledgers_owner_id_fkey(full_name)`،
  ثم `ledger_balances`. لا يمكن دمجهما في استعلام واحد، لأن PostgREST لا
  يرى علاقة مع الواجهة (`PGRST200`).
- `buildSummaries` تقلب الإشارة لغير المالك، فيكون الرصيد دائماً من جهتي
  (موجب = «لك»، سالب = «عليك»).
- العنوان: عند المالك اسم الطرف (والمحل تحته)، وعند الزبون اسم المحل (أو
  المالك) واسم المالك تحته.
- لكل دفتر: «N بانتظار التأكيد»، و«N معترض عليه»، و«لم ينضم بعد».
- مجموع «لك» ومجموع «عليك» لكل عملة، والسحب للتحديث (يُبقي القائمة عند
  الفشل)، وإعادة المحاولة عند فشل أول تحميل، وشريط «أُضيف إلى حسابك N دفاتر».
- الترتيب حسب حجم الرصيد المتفق عليه، ثم الاسم.
- المبالغ: `45.50 ر.س`، و`5,000 ر.س` (بلا `.00`).
- **البحث والترتيب** (`dain-37`، على القائمة المحمّلة، بلا migration): حقل
  بحث تحت المجاميع يطابق اسم الطرف والمحل أو المالك تحته، ورقم الطرف للمالك.
  `searchKey` يوحّد الهمزات والتاء المربوطة والألف المقصورة ويحذف التشكيل
  والتطويل ويحوّل الأرقام العربية؛ ورقم محلي بصفره الأول يطابق المخزّن (يكفي
  رقمان). شرائح الترتيب: الأكبر رصيداً (الافتراضي)، والاسم، والمعلّق أولاً،
  وموعد السداد (الأقرب أولاً، وبلا موعد أخيراً). المجاميع تشمل كل الدفاتر
  دائماً، والسحب للتحديث يُبقي البحث.
- «فات موعد السداد» أو «السداد d/m/y» على الدفتر الذي له موعد.
- **العودة إلى التطبيق** (`dain-39`، `AppLifecycleListener`): تُعاد قراءة
  القائمة إن كانت الشاشة الظاهرة، وإلا تعيد شاشة الدفتر الظاهرة قراءة نفسها،
  والقائمة تُقرأ عند إغلاقها كما كانت. لا Realtime: الحد المجاني 200 اتصال
  متزامن، وإعادة القراءة استعلامان فقط.

**«دفتر جديد»** (`OpenLedgerScreen` + `OpenLedgerController`)، من زر
`New ledger / دفتر جديد` في «دفاتري»، ثم تُفتح شاشة الدفتر الجديد مباشرة:

- اسم الطرف ورقمه (`normalizePhone`)، و«الدفتر باسم»: شخصي، أو أحد محلاتي،
  أو «محل جديد» بالاسم، و«العملة»: ر.ي / ر.س / $ (`YER`/`SAR`/`USD`). الافتراضي
  من رقم الطرف (`967` ← ر.ي، وغيره ← ر.س) ويتبعه أثناء الكتابة حتى يُختار
  يدوياً. **العملة لا تتغيّر بعد فتح الدفتر** (غير ممنوحة في التعديل، `42501`)،
  لأن تغييرها يغيّر معنى كل المبالغ. الرمز من `currencySymbol` في التطبيق
  و`share/dain-share.js` معاً. والتذكير لا يُضبط هنا.
- رقمي أنا يُرفض قبل أي كتابة: القاعدة تقبله، لكن `link_my_ledgers` لا تربط
  دفتراً بمالكه، فيبقى «لم ينضم بعد» للأبد. رقمي من `auth.currentUser.phone`.
- المحل الجديد يُنشأ بطلب منفصل قبل الدفتر. بعد إنشائه يصبح هو المختار،
  فإعادة المحاولة بعد فشل الدفتر لا تنشئ محلاً ثانياً (بلا migration).
- `23505` من المفتاح الفريد له رسالة في المتحكم (لا في `errors.dart` لأن
  الرمز نفسه يظهر في جداول أخرى): «لهذا الرقم دفتر في هذا المحل بالفعل.» أو
  «لديك دفتر شخصي لهذا الرقم بالفعل.».
- `fetchMyBusinesses` يصفّي بـ `owner_id = me`، لأن RLS يُظهر للزبون محل
  المالك أيضاً بعد الربط.

**شاشة الدفتر** (`LedgerScreen` + `LedgerController`)، بالضغط على دفتر، والقائمة
تُعاد قراءتها عند العودة:

- الرصيد المتفق عليه من جهتي، و«مع المعلّق»، وعدد المعلّق والمعترض عليه، وتنبيه
  «لم ينضم بعد». `fetchLedger(id)` يبني الملخص بنفس `buildSummaries`.
- القيود من الأحدث (`occurred_on` ثم `created_at` تنازلياً)، وكل قيد من جهتي:
  «أعطيت» (موجب) أو «أخذت» (سالب)، والتاريخ، ومن سجّله، والحالة («بانتظار
  تأكيدك» لقيود الطرف الآخر)، والرد.
- زرّا `أعطيت` و`أخذت` يسجّلان قيداً معلّقاً بمبلغ (`parseMoney`: أرقام
  عربية، و`.` أو `٫`، وخانتان عشريتان كحد أقصى) وملاحظة اختيارية ≤200،
  و**تاريخ** (`dain-36`): اليوم المحلي افتراضياً، وزر «التاريخ: اليوم» يفتح
  منتقي التاريخ حتى خمس سنوات للخلف ولا بعد اليوم. المتحكم يرفض ما بعد اليوم
  (`LedgerController.futureDayMessage`)، والقاعدة ترفضه أيضاً (`22023`، الرسالة
  نفسها).
- **موعد السداد** (`dain-38`): يضعه المالك أو يزيله من نافذة الجرس («التذكير
  وموعد السداد»)، سنة للخلف حتى خمس للأمام. يراه الطرفان في بطاقة الرصيد،
  و«فات الموعد» بالأحمر حين يمرّ ورصيد متفق عليه قائم (`paymentOverdue`). لا
  يغيّر أي رصيد. `setDueDate` من الطرف الآخر لا يجد صفاً (`StateError`).
- **الاتجاه يُخزَّن نسبةً للمالك**: `entryDirection` تجعل «أعطيت» من الطرف الآخر
  `in`، و`buildEntries` تعيده إلى جهتي. الإدراج بالأعمدة المسموحة فقط.
- الضغط على قيد يعرض الإجراءات التي تسمح بها القاعدة فقط (`entryActions`):
  للطرف الآخر «تأكيد» و«اعتراض» على المعلّق، و«تأكيد» على المعترض عليه؛
  وللمنشئ «سحب القيد» بضغطة ثانية. المؤكد والمسحوب نهائيان.
- **سبب الاعتراض إجباري** (1..200، يُخزَّن في `response_note`) ليعرف المنشئ
  ماذا يصحّح. التطبيق والصفحة يتحققان منه، والقاعدة تفرضه أيضاً
  (`20261021000000`) على من يستدعي الدوال مباشرة.
- إن سبق الطرفُ الآخر (`55000`): «تغيّرت حالة هذا القيد. أُعيد تحميل الدفتر.»
  ويُعاد التحميل، فتعرض النافذة الحالة الجديدة.

**رابط للطرف الآخر** (المالك فقط، زر الرابط في شريط شاشة الدفتر):

- `create_share_link` (30 يوماً) يرجع الرمز مرة واحدة؛ يُبنى الرابط
  `DainConfig.shareUrl(token)` = `shareBaseUrl#token` ويُنسخ (`Clipboard`، بلا
  تبعية). الرمز بعد `#` فلا يصل إلى أي خادم أو سجل.
- «رابط جديد» يُبطل السابق، و«إيقاف الرابط» (`revoke_share_link`) يُبطله.
  الرمز لا يُقرأ ثانية (يُخزَّن SHA-256 فقط)، فيظهر في الجلسة التي أُنشئ فيها.
- بعد إنشائه، «إرساله عبر واتساب» (`dain-41`) يفتح محادثة مع رقم الطرف وفيها
  `shareLinkMessage`.

**صفحة الرابط** (`share/`، لمن لا يملك التطبيق، بدور `anon`):

- `fetch` إلى `/rest/v1/rpc/get_shared_ledger` و`respond_by_token` بترويسة
  `apikey` فقط (المفتاح المنشور يكفي، وCORS يسمح بأي أصل).
- تعرض الدفتر **من جهة الزائر**: الرصيد مقلوب، و`out` من المالك = «أخذت».
  التأكيد والاعتراض على قيود المالك فقط (`can_respond`)، والاعتراض على
  المعلّق فقط، و**سبب الاعتراض إجباري** كما في التطبيق.
- الأسماء والملاحظات (يكتبها المالك) تُعرض بـ `textContent` فقط، وCSP يمنع أي
  سكربت أو اتصال غير Supabase. `P0002` = رابط غير صالح أو منتهٍ، بلا إعادة
  محاولة؛ و`55000` يعيد التحميل.
- **كشف الحساب** (`dain-40`): زر «طباعة الكشف أو حفظه PDF» يفتح نافذة الطباعة
  في المتصفح، فلا تبعية. على الورق: سطر «كشف حساب الاسم حتى اليوم»، وخلفية
  بيضاء، بلا أزرار (`@media print` في `index.html`، و`.print-only`/`.no-print`).
- رابط «سياسة الخصوصية» أسفل الصفحة إلى `privacy.html`.

**سياسة الخصوصية** (`share/privacy.html`، `dain-40`): ثابتة بلا سكربت وCSP
`default-src 'none'`، ينشرها `pages.yml` مع الصفحة على
`https://abdulmannany.github.io/dain/privacy.html`. تصف ما يُحفظ، والدفاتر
المسجّلة برقمك، ومن يرى، والمعالجين (Supabase فرانكفورت، وبوابة SMS،
وGitHub)، والحذف وما يبقى عند الآخرين. التواصل عبر Issues في المستودع.
**أي تغيير في البيانات المحفوظة يحتاج تحديثها.**

**محلاتي** (`ShopsScreen` + `ShopsController`، زر المتجر في شريط «دفاتري»):

- الضغط على محل: إعادة تسمية (1..80 بعد القصّ)، أو حذف بضغطة ثانية.
- المحل الذي فيه دفاتر لا يُحذف: القاعدة ترفض (`23503`، المفتاح الأجنبي)
  لأن الدفتر سجل مشترك لا يُحذف. لا migration: `update (name)` و`delete`
  ممنوحان أصلاً وRLS يحصرهما في المالك (صف فارغ لغيره ← «المحل غير موجود.»).

**التذكير** (المالك فقط؛ لا SMS ولا إشعارات، فيرسله المالك بنفسه):

- زر الجرس في شاشة الدفتر: إيقاف أو كل 3/7/14/30 يوماً (`remind_every_days`،
  ممنوح التعديل أصلاً للمالك).
- `reminderDue`: مستحق حين يكون للمالك رصيد **متفق عليه** موجب ومرّت المدة منذ
  آخر تذكير (أو لم يُرسل قط). يظهر «تذكير مستحق» في «دفاتري» وزر في بطاقة
  الرصيد.
- الزر ينشئ رابطاً جديداً (يُبطل السابق)، وينسخ `reminderMessage` (الاسم والمحل
  والمبلغ وموعد السداد إن وُجد والرابط)، ثم `mark_reminded` يسجّل الوقت
  **بساعة الخادم** (`last_reminded_at` غير ممنوح التعديل)، ثم يفتح واتساب
  (`dain-41`): `whatsappUrl` = `https://wa.me/<الرقم المخزّن>?text=<النص مرمّزاً
  بـ %>` (لا `+` للمسافة). إن لم يُفتح شيء تبقى الرسالة منسوخة ويقول ذلك.

**التسوية** (`dain-44`، migration `20261027000000`):

- الدفعة قيد من نوع `payment`، تمرّ بدورة القيد نفسها (معلّق ← مؤكد أو معترض
  عليه، والسحب)، والرصيد المتفق عليه (`ledger_balances`) يبقى المصدر الوحيد
  للمتبقي. لم يُضف جدول دفعات منفصل: كان سيجعل للرصيد مصدرين، ويعيد كتابة
  التأكيد والاعتراض وصفحة الرابط.
- زر في بطاقة الرصيد: «استلمت سداداً» حين يكون لي عليه، و«سدّدت» حين يكون عليّ،
  ويختفي حين لا يبقى ما يُسدَّد. النافذة تبدأ بالمتبقي كاملاً (`plainAmount`)
  وتقبل أقل منه، مع التاريخ والملاحظة. القيد يظهر «سدّدت X» أو «استلمت سداداً X»
  في التطبيق وصفحة الرابط.
- `paymentRoomOf` = الرصيد المتفق عليه من جهة الدافع ناقص دفعاته المعلّقة
  والمعترض عليها، كما يحسبه الـ trigger. المتحكم يرفض ما فوقه قبل الإرسال، وإن
  رفضته القاعدة (`23514`، سبقه الطرف الآخر) تظهر «السداد أكبر من المتبقي الآن.
  أُعيد تحميل الدفتر.» ويُعاد التحميل.
- **لا تسجيل مرتين:** `LedgerController` يصنع `id` للقيد ويحتفظ به ما دام القيد
  نفسه يُعاد إرساله (المبلغ والاتجاه والملاحظة واليوم والنوع)، فإن وصل الإرسال
  الأول وضاع جوابه يعود الثاني بـ `23505` فيُعدّ محفوظاً. قيد مختلف = `id` جديد.
  يسري على كل القيود، لا الدفعات فقط.

**سجل القيد والإيصال** (`dain-45`، migration `20261028000000`): الضغط على قيد
يعرض «السجل» من `entry_events` (`eventLine`: «أُكّد · الطرف الآخر · 22/10/2026
09:05»، و«عبر الرابط» لمن رد من الصفحة، و«غير معروف» للحساب المحذوف وللردود
الأقدم من السجل). وللدفعة إيصال (`paymentReceipt`): الرقم (أول 8 أحرف من `id`)،
والمبلغ، ومن، وإلى، والتاريخ، والحالة، وزر ينسخه للإرسال. النافذة صارت تُمرَّر.

**حسابي** (`AccountScreen`، زر الشخص في شريط «دفاتري»):

- تغيير اسمي كما يراه الآخرون (`profiles.full_name`، 1..80).
- «سياسة الخصوصية» تفتح `DainConfig.privacyUrl` في المتصفح (`dain-41`).
- **حذف الحساب** بضغطة ثانية (يشترطه Google Play): `delete_my_account()`
  يحذف مستخدم auth، فيُحذف ملفي ومحلاتي والدفاتر التي فتحتها بقيودها. الدفتر
  الذي يملكه غيري سجل مشترك يبقى معه: يُفصل عني (`counterparty_id` ← null)،
  وقيودي فيه تبقى بلا مؤلف (`created_by` ← null، migration `20261024000000`)،
  فلا يتحرك رصيده. القيد بلا مؤلف: يؤكده المالك أو يعترض عليه، ولا يسحبه
  أحد، والرابط لا يجيب عنه (`respond_by_token` صار `is distinct from`).
  بعد الحذف يُسجَّل الخروج محلياً وتعود شاشة الرقم.

**تعديل الطرف الآخر** (للمالك، زر القلم في شاشة الدفتر): الاسم دائماً، والرقم
حتى ينضم (بعده ترفضه القاعدة بـ `55000` والحقل معطّل). الرقم الجديد يُطبَّع،
ويُرفض رقمي، و`23505` إن كان لدفتر آخر في نفس المحل، ويحذف رابط المشاركة
(المُشغّل `ledgers_guard_phone`). لا migration: العمودان ممنوحان أصلاً.

**غير مبني بعد:** اللوحة المالية (المحصّل والمدفوع في فترة)، وتذكير يُرسل
تلقائياً، والإشعارات الفورية، وقفل التطبيق، وجهات الاتصال، وصورة الفاتورة،
والأقساط.

**التبعيات:** `supabase_flutter ^2.18.3` و`flutter_localizations` (SDK)
و`url_launcher ^6.3.3` (`dain-41`، بموافقة المالك). `url_launcher` كان في القفل
وفي APK أصلاً عبر `supabase_flutter`، فلم تُضف حزمة ولا كود أصلي. الروابط
تُفتح عبر `openUrl` في `lib/core/open_url.dart`، والاختبارات تستبدله.
`AndroidManifest.xml` يعلن استعلام `VIEW https` الذي يطلبه على Android 11+.
لا Riverpod؛ الحالة عبر `ChangeNotifier` + `ListenableBuilder`. أي تبعية
جديدة تحتاج موافقة.

دروس الجلسة:

- `sms_send_failed` مع `AC000…` يعني أن أرقام الاختبار غير مفعّلة: إما صيغة
  الحقل خاطئة، أو تاريخ الصلاحية فارغ، أو الحفظ تم في القسم الخطأ.
- رفض الدفع بسبب `workflow scope` حلّه صلاحية Workflows في التوكن، لا تعديل الملفات.
- `dart:io` لا يُستورد في `lib/` لأن التطبيق يُبنى للويب أيضاً.
- **APK الإصدار كان يفتح على شاشة بيضاء**: `main()` كانت تنتظر
  `Supabase.initialize` قبل `runApp`، فأي فشل لا يُرى. `DainBoot` يرسم أولاً
  ويعرض الخطأ، فظهر السبب: `shared_preferences_android` 2.5.x يستدعي
  `SharedPreferencesApiRegistrar.getAll` عبر JNI بالاسم، وR8 يغيّر الأسماء في
  الإصدار ← `NoSuchMethodError`. الحل: قيد `>=2.4.28 <2.5.0` في `pubspec.yaml`
  (يعود تنفيذ method channel، ويخرج `jni` من القفل)، و`release_plugins_test.dart`
  يمنع رجوعه. اختبارات الواجهة ونسخ debug لا ترى أخطاء R8 أبداً.
- الاختبار الحي يفشل إن دخلت جهة أخرى بالرقم `0500000002` أثناءه (يُربط الدفتر
  قبله فيعيد `0`)؛ لا يُشغَّل اختباران حيّان معاً.
- Supabase يرفض رمزاً ثانياً للرقم نفسه خلال نحو دقيقة
  (`over_sms_send_rate_limit`)، حتى لأرقام الاختبار. لذلك كان الاختبار الحي
  الثاني يفشل دائماً على `2e48034`، ولذلك يُفصل بين سكربتين يشغّلان الاختبار
  الحي بدقيقة.
- في supabase_dart الدالة `.order()` **تنازلية افتراضياً**؛ التصاعدي يحتاج
  `ascending: true` صراحةً.
- في اختبارات الواجهة: `tester.pageBack()` يبحث عن تلميح `Back` الإنجليزي،
  والتطبيق عربي، فيُستخدم `find.byType(BackButton)`. و`find.descendant` لا
  يطابق الجذر نفسه إلا مع `matchRoot: true`.
- PostgREST يرجع `P0002` بحالة HTTP 500؛ الصفحة تقرأ `code` من JSON لا الحالة.
- لا CI ولا Pages يُجرَّبان من الجلسة (APK يحتاج Android SDK، وgithub.io غير
  مسموح)؛ يُتحقَّق منهما في صفحة Actions بعد الدفع. سجلات الخطوات تحتاج
  تسجيل الدخول، فتُطلب لقطة منها.
- PKCS12 يرد `keystore password was incorrect` لكلمة سر خاطئة **ولملف تالف**
  معاً (فحص MAC)؛ فحص `keytool -list` قبل البناء يفرّق بثوانٍ.
- GitHub يخفي قيم الأسرار في السجلات أينما ظهرت: `upload` صار `***` حتى في
  `actions/***-artifact` و`***-keystore.jks`.
- (`dain-36..43`) **عمود جديد يقرؤه التطبيق يكسر التحميل** حتى يُلصق الـ
  migration: بعد `dain-38` كل `fetchMine` و`fetchLedger` يطلبان `due_on`. لذلك
  جُرّب الاختبار الحي من الجلسة على `dain-37` فقط: الاثنا عشر القديمة نجحت،
  والجديد فشل عند حارس القاعدة برسالة «apply … first» كما يجب.
- `url_launcher` كان «transitive» في `pubspec.lock` عبر `supabase_flutter`:
  تسميته غيّرت سطراً واحداً في القفل.
- منتقي التاريخ بالعربية في الاختبارات: أرقام لاتينية، وزر «حسنًا»، وتلميح
  «الشهر السابق». `AppLifecycleListener` يُختبر بسلسلة الحالات كاملة عبر
  `handleAppLifecycleStateChanged`.
- `pg_dump` يحتاج نفس الإصدار أو أحدث من الخادم: `postgres:18` في Docker.
  الاتصال المباشر بـ Supabase IPv6 فقط، فالنسخ عبر Session pooler.
- (`dain-44..47`) **التزامن لا يظهر في جلسة واحدة**: فحوص `ledger_flow_test.sql`
  مرّت مع trigger بلا قفل؛ `concurrency_test.sh` بخمس جلسات متوازية، كل منها
  تُبقي معاملتها مفتوحة ثانية، أظهر 5 دفعات من 30 على 100 حين أُزيل القفل.
- الكتابة في view (`ledger_balances`) ترفضها Postgres بـ `55000` قبل فحص
  الصلاحيات، لا بـ `42501`.
- **أي مفتاح جديد في `get_shared_ledger`** يكسر الاختبار الحي لصفحة الرابط، لأنه
  يقارن مفاتيح القيد حرفياً (عقد `share/`). أول تشغيل لـ `dain-44` على الجوال
  فشل هناك بسبب `kind`، فأُعيد السكربت بالاختبار محدَّثاً. قبل تعديل الدالة: ابحث
  عن `keys.toSet()` في `test/live`.
- trigger بصلاحيات المستدعي لا يقفل صف دفتر لا تسمح RLS للطرف الآخر بتعديله،
  لذلك `_entries_guard_payment` security definer.
- `tools/patchgen/gen.py` يفشل حين يقع تغييران متقاربان في ملف واحد (سياق مرساة
  الثاني يدخل في نص غيّره الأول). سكربتات 36..47 وُلّدت بنسخة محلية تدمج
  التغييرات المتقاربة في مرساة واحدة؛ الأداة في المستودع لم تُعدَّل بعد.

## 9. الخطوة التالية المقترحة

1. **اللوحة المالية** على بيانات التسوية: لكل عملة على حدة لي وعليّ، والمحصّل
   والمدفوع في فترة (دفعات مؤكدة)، والمعلّق والمعترض عليه منفصلين، والمتأخر
   والمستحق قريباً، وأكثر المدينين.
2. كشف الحساب بالرصيد السابق والحركات والدفعات والرصيد النهائي، وCSV.
3. حذف رقم المالك من الأرقام التجريبية (خطاف SMS يعمل: Delivered على الجوال).
   لاحقاً عند الكثرة: واتساب (رمز بالعكس) أو مزوّد مدفوع، ثم التذكير التلقائي.
4. تجهيز المتجر: الأيقونة وAAB (رابط الخصوصية جاهز).
5. قفل التطبيق بالبصمة (`local_auth` و`FlutterFragmentActivity`)، ثم الإشعارات
   الفورية (FCM، بعد مشروع Firebase من المالك).
6. إصلاح `gen.py` في المستودع بدمج التغييرات المتقاربة.
7. رفع قيد `shared_preferences_android` حين يُصلح upstream قواعد R8 لـ JNI.
